# Advanced features: PostgreSQL, CockroachDB and beyond

psql renders one query for several products, but the products do not all
speak the same SQL. This page covers the features that go beyond the portable
core: how psql tells the products apart, what each feature renders on each
of them, and what happens where a feature does not exist. Every example on
this page compiles and was run against the library.

## Products, variants and feature flags

An `Engine` groups wire-compatible products: `EnginePostgreSQL` covers
PostgreSQL and CockroachDB, `EngineMySQL` covers MySQL and MariaDB. Where
their SQL differs, the `Variant` tells them apart:

```go
be, err := psql.New(dsn)
fmt.Println(be.Engine(), be.Variant(), be.ServerVersion()) // e.g. "PostgreSQL Engine CockroachDB CockroachDB CCL v24.1.0"
```

- `be.Variant()` returns `VariantPostgreSQL`, `VariantCockroachDB`,
  `VariantMySQL`, `VariantMariaDB` or `VariantSQLite`. The driver detects the
  product when connecting (CockroachDB and MariaDB report themselves in
  their version string); when nothing was detected the engine's primary
  product is assumed.
- `be.ServerVersion()` is the version string reported by the server, or `""`
  when the driver did not record one. Version-dependent rendering (MySQL 5.7
  vs 8.0 lock syntax, `EXPLAIN ANALYZE` on MySQL 8.0.18+) treats an unknown
  version as recent.
- `be.Supports(feature)` answers for the `Feature*` constants below. A
  driver whose dialect implements `VariantAware` answers authoritatively;
  otherwise psql applies the engine-level defaults shown in the matrix.
- Backends built with `psql.NewBackend(engine, db, psql.WithVariant(v),
  psql.WithServerVersion(s))` carry an explicit variant, which is how the
  render-only examples below target CockroachDB without a server.

Rendering a feature the product lacks fails with an error wrapping
`psql.ErrNotSupported`, before anything is sent to the database:

```go
if be.Supports(psql.FeatureAsOfSystemTime) {
    // CockroachDB: follower reads are available
}
_, err := psql.B().Select().From("t").AsOfSystemTime("-10s").Render(ctx)
if errors.Is(err, psql.ErrNotSupported) {
    // not CockroachDB
}
```

Rendering without a backend (a context without one, or `psql.Escape`) is
permissive: every feature renders in its default form, so queries can be
previewed.

## RETURNING

`Returning(fields...)` appends a `RETURNING` clause to an `INSERT`,
`INSERT ... SELECT`, `UPDATE`, `DELETE` or `REPLACE`. Strings are column
names (`"*"` selects every column); expressions such as `psql.F`,
`psql.Raw` or `psql.Coalesce` are accepted. The rows come back through
`RunQuery`, or scanned into objects by column name with `RunQueryT` /
`RunQueryTOne`:

```go
// UPDATE "users" SET "active"=$1 WHERE ("id"=$2) RETURNING *
users, err := psql.RunQueryT[User](ctx, psql.B().Update("users").
    Set(map[string]any{"active": false}).
    Where(map[string]any{"id": 42}).
    Returning("*"))

// INSERT INTO "users" ("email","login") VALUES ($1,$2) RETURNING "id","created"
user, err := psql.RunQueryTOne[User](ctx, psql.B().Insert().Table("users").
    Set(map[string]any{"email": "a@example.com", "login": "a"}).
    Returning("id", "created"))

// DELETE FROM "sessions" WHERE ("expires"<NOW()) RETURNING "id",now() AS deleted_at
rows, err := psql.B().Delete().From("sessions").
    Where(psql.Lt(psql.F("expires"), psql.Now())).
    Returning("id", psql.Raw("now() AS deleted_at")).
    RunQuery(ctx)
```

Objects returned by `RunQueryT` are regular tracked objects: columns that
were not returned keep their zero value, and `psql.Update` works on them.
`RETURNING` expressions are never bound as arguments. MariaDB supports
`RETURNING` on `INSERT`, `REPLACE` and `DELETE` but not on `UPDATE`; MySQL
has no `RETURNING` at all. On `SELECT` queries `Returning` is always an
error.

The object functions use `RETURNING` on their own where the driver reports
it: `psql.Insert` refreshes the inserted objects with the stored row, and
`BulkInsert` reads generated keys back that way.

## Upserts: Excluded, OnConflictConstraint, DoUpdateWhere

`psql.Excluded("col")` refers, in the update part of an upsert, to the value
that would have been inserted. It renders as `EXCLUDED."col"` with the
`ON CONFLICT` syntax and as `VALUES("col")` with MySQL's
`ON DUPLICATE KEY UPDATE`, which makes it the portable way to write an
upsert:

```go
q := psql.B().Insert().Table("counters").
    Set(map[string]any{"id": 1, "hits": 1, "name": "x"}).
    OnConflict("id").
    DoUpdate(map[string]any{"hits": psql.Excluded("hits"), "name": psql.Excluded("name")})
// PostgreSQL, CockroachDB, SQLite:
//   INSERT INTO "counters" ("hits","id","name") VALUES ($1,$2,$3)
//   ON CONFLICT ("id") DO UPDATE SET "hits"=EXCLUDED."hits","name"=EXCLUDED."name"
// MySQL, MariaDB:
//   INSERT INTO "counters" SET "hits"=?,"id"=?,"name"=?
//   ON DUPLICATE KEY UPDATE "hits"=VALUES("hits"),"name"=VALUES("name")
```

Two PostgreSQL-style refinements:

- `OnConflictConstraint(name)` names the unique or exclusion constraint
  instead of listing columns (`ON CONFLICT ON CONSTRAINT "name"`). It
  cannot be combined with `OnConflict` columns and exists on PostgreSQL and
  CockroachDB only.
- `DoUpdateWhere(conds...)` restricts the `DO UPDATE` action to matching
  rows (`DO UPDATE SET ... WHERE ...`), with the same condition forms as
  `Where`; both the target row and `Excluded` values may be referenced.
  Available on PostgreSQL, CockroachDB and SQLite; MySQL and MariaDB have
  no equivalent.

```go
psql.B().Insert().Table("counters").
    Set(map[string]any{"id": 1, "hits": 1}).
    OnConflictConstraint("counters_pkey").
    DoUpdate(map[string]any{"hits": psql.Excluded("hits")}).
    DoUpdateWhere(psql.Lt(psql.F("counters", "hits"), 100))
// INSERT INTO "counters" ("hits","id") VALUES ($1,$2)
// ON CONFLICT ON CONSTRAINT "counters_pkey" DO UPDATE SET "hits"=EXCLUDED."hits" WHERE ("counters"."hits"<$3)
```

`DoNothing` keeps the `OnConflict` target when one is given
(`ON CONFLICT ("id") DO NOTHING`); SQLite still renders `INSERT OR IGNORE`
and MySQL `INSERT IGNORE`.

## Common table expressions

`With(name, sub, columns...)` adds a `WITH` clause ahead of the main query;
`sub` is a `*psql.QueryBuilder` or, for queries the builder cannot express,
a `psql.Raw`. The CTE is then a table like any other for `From`, `Join` or
subqueries. Arguments of the CTE are numbered before those of the main
query. CTEs exist on every supported product (MySQL 8.0+, MariaDB 10.2+,
SQLite 3.8.3+).

```go
active := psql.B().Select("id").From("users").Where(map[string]any{"active": true})
q := psql.B().With("active_users", active).
    Select("*").From("orders").
    Where(map[string]any{"user_id": &psql.SubIn{Sub: psql.B().Select("id").From("active_users")}})
// WITH "active_users" AS (SELECT "id" FROM "users" WHERE ("active"=$1))
// SELECT * FROM "orders" WHERE ("user_id" IN (SELECT "id" FROM "active_users"))

// a column list, and the CTE joined
counts := psql.B().Select("user_id", psql.Raw("COUNT(*)")).From("orders").GroupByFields("user_id")
q = psql.B().With("oc", counts, "uid", "cnt").
    Select("u.login", "oc.cnt").From("users u").
    Join("LEFT", "oc", psql.Equal(psql.F("oc.uid"), psql.F("u.id")))
// WITH "oc" ("uid","cnt") AS (SELECT "user_id",COUNT(*) FROM "orders" GROUP BY "user_id")
// SELECT "u"."login","oc"."cnt" FROM "users" AS "u" LEFT JOIN "oc" ON "oc"."uid"="u"."id"
```

`WithRecursive` marks the CTE as recursive; the whole clause is rendered as
`WITH RECURSIVE` when at least one CTE is. Since the builder has no `UNION`,
the recursive part is normally written with `psql.Raw`:

```go
tree := psql.Raw(`SELECT "id","parent" FROM "nodes" WHERE "id"=1 UNION ALL SELECT n."id",n."parent" FROM "nodes" n JOIN "tree" t ON n."parent"=t."id"`)
q := psql.B().WithRecursive("tree", tree, "id", "parent").Select("*").From("tree")
// WITH RECURSIVE "tree" ("id","parent") AS (SELECT ... UNION ALL SELECT ...) SELECT * FROM "tree"
```

CTEs also prefix `UPDATE`, `DELETE`, `INSERT` and `INSERT ... SELECT`
statements. MySQL and MariaDB only accept `WITH` in front of the `SELECT`
part of an `INSERT ... SELECT`, and psql renders it there on those
products.

```go
expired := psql.B().Select("id").From("jobs").Where(psql.Lt(psql.F("expires"), psql.Now()))
q := psql.B().With("expired", expired).Delete().From("jobs").
    Where(map[string]any{"id": &psql.SubIn{Sub: psql.B().Select("id").From("expired")}})
// WITH "expired" AS (SELECT "id" FROM "jobs" WHERE ("expires"<NOW()))
// DELETE FROM "jobs" WHERE ("id" IN (SELECT "id" FROM "expired"))
```

## DISTINCT ON

`DistinctOn(fields...)` keeps the first row of each group of rows sharing
the given expressions. The leading `ORDER BY` expressions should match; a
`SetDistinct()` on the same query is superseded. PostgreSQL and CockroachDB
only (`FeatureDistinctOn`).

```go
// latest event per user
q := psql.B().Select("*").DistinctOn("user_id").From("events").
    OrderBy(psql.S("user_id", "ASC"), psql.S("created", "DESC"))
// SELECT DISTINCT ON ("user_id") * FROM "events" ORDER BY "user_id" ASC,"created" DESC

latest, err := psql.RunQueryT[Event](ctx, q)
```

## Row lock modes

`SetLockMode(mode)` chooses the lock a `SELECT` takes on the rows it
returns; `SetForUpdate()` is `SetLockMode(psql.LockUpdate)`.

| Mode | PostgreSQL / CockroachDB | MySQL 8 | MariaDB, MySQL 5.7 | SQLite |
|------|--------------------------|---------|--------------------|--------|
| `LockUpdate` | `FOR UPDATE` | `FOR UPDATE` | `FOR UPDATE` | omitted |
| `LockShare` | `FOR SHARE` | `FOR SHARE` | `LOCK IN SHARE MODE` | omitted |
| `LockNoKeyUpdate` | `FOR NO KEY UPDATE` | `FOR UPDATE` | `FOR UPDATE` | omitted |
| `LockKeyShare` | `FOR KEY SHARE` | `FOR SHARE` | `LOCK IN SHARE MODE` | omitted |

`LockOf(tables...)` restricts the lock to the rows of the listed tables or
aliases (`FOR UPDATE OF "t"`; it implies `LockUpdate` when no mode was set)
and is available on PostgreSQL, CockroachDB and MySQL 8: MariaDB and MySQL
5.7 fail with `ErrNotSupported`. `SetSkipLocked()` and `SetNoWait()` follow
the clause. SQLite locks the whole database, so the clause is silently
omitted there.

```go
psql.B().Select().From("jobs").Where(map[string]any{"state": "queued"}).SetLockMode(psql.LockShare)
// SELECT * FROM "jobs" WHERE ("state"=$1) FOR SHARE

psql.B().Select().From("jobs").SetLockMode(psql.LockNoKeyUpdate).SetSkipLocked().Limit(1)
// SELECT * FROM "jobs" LIMIT 1 FOR NO KEY UPDATE SKIP LOCKED

psql.B().Select().From("jobs j").
    Join("INNER", "users u", psql.Equal(psql.F("u.id"), psql.F("j.user_id"))).
    LockOf("j").SetNoWait()
// SELECT * FROM "jobs" AS "j" INNER JOIN "users" AS "u" ON "u"."id"="j"."user_id" FOR UPDATE OF "j" NOWAIT
```

The fetch options expose the same modes for `Fetch`, `Get`, `FetchOne` and
the iterators. Row locks only mean something inside a transaction:

```go
err := psql.Tx(ctx, func(ctx context.Context) error {
    jobs, err := psql.Fetch[Job](ctx, map[string]any{"State": "queued"},
        psql.WithLock(psql.LockShare), psql.FetchLockSkipLocked)
    if err != nil {
        return err
    }
    job, err := psql.Get[Job](ctx, map[string]any{"ID": uint64(1)}, psql.FetchLockKeyShare)
    if err != nil {
        return err
    }
    job.State = "running"
    return psql.Update(ctx, job)
})
```

| Option | Effect |
|--------|--------|
| `psql.FetchLock` | `FOR UPDATE` (with `psql.FetchLockSkipLocked` / `psql.FetchLockNoWait` modifiers) |
| `psql.FetchLockShare` | `LockShare` |
| `psql.FetchLockNoKeyUpdate` | `LockNoKeyUpdate` |
| `psql.FetchLockKeyShare` | `LockKeyShare` |
| `psql.WithLock(mode, tables...)` | any mode, optionally restricted with `LockOf` |

## AS OF SYSTEM TIME (CockroachDB)

`AsOfSystemTime(expr)` reads from a historical snapshot; `expr` is an
interval relative to now (`"-10s"`) or a timestamp, embedded as a string
literal after the `FROM` tables and joins. It is the CockroachDB way to do
cheap follower reads. The query must not run inside a transaction unless
that transaction was itself started `AS OF SYSTEM TIME`. Any other product
fails with `ErrNotSupported` (`FeatureAsOfSystemTime`).

```go
psql.B().Select().From("orders").AsOfSystemTime("-10s").Where(map[string]any{"user_id": 7})
// SELECT * FROM "orders" AS OF SYSTEM TIME '-10s' WHERE ("user_id"=$1)

orders, err := psql.Fetch[Order](ctx, nil, psql.AsOfSystemTime("-10s"))
n, err := psql.Count[Order](ctx, nil, psql.AsOfSystemTime("2024-01-15 12:00:00"))
```

## EXPLAIN

`Explain(ctx, analyze)` runs the product's query plan statement for the
query and returns the plan as text, one row per line (multi-column plans
are tab-separated). With `analyze` the query is really executed, timing
included, which also applies to `INSERT`, `UPDATE` and `DELETE` queries.

| Product | `analyze == false` | `analyze == true` |
|---------|--------------------|-------------------|
| PostgreSQL, CockroachDB | `EXPLAIN` | `EXPLAIN ANALYZE` |
| MySQL | `EXPLAIN` | `EXPLAIN ANALYZE` (8.0.18+, `ErrNotSupported` before) |
| MariaDB | `EXPLAIN` | `ANALYZE` |
| SQLite | `EXPLAIN QUERY PLAN` | `EXPLAIN QUERY PLAN` (analyze ignored) |

```go
plan, err := psql.B().Select().From("users").Where(map[string]any{"Email": "a@example.com"}).Explain(ctx, false)
fmt.Println(plan) // SQLite: 3	0	39	SEARCH users USING INDEX users_email (Email=?)
```

Rendering errors (an unsupported clause, a bare string condition) are
returned before anything is sent.

## Multi-row inserts

`Insert` / `Set` express a single row. `InsertRows(columns, rows...)` and
`Values(maps...)` add any number of rows in column-list form, which every
product accepts:

```go
psql.B().InsertRows([]string{"id", "name"}, []any{1, "a"}, []any{2, "b"}).Table("users")
// INSERT INTO "users" ("id","name") VALUES ($1,$2),($3,$4)     (PostgreSQL)
// INSERT INTO "users" ("id","name") VALUES (?,?),(?,?)         (MySQL, SQLite)

psql.B().Values(
    map[string]any{"id": 1, "name": "a"},
    map[string]any{"id": 2, "name": psql.Raw("upper('b')")},
).Table("users").
    OnConflict("id").DoUpdate(map[string]any{"name": psql.Excluded("name")}).
    Returning("id")
// INSERT INTO "users" ("id","name") VALUES (?,?),(?,upper('b'))
// ON CONFLICT ("id") DO UPDATE SET "name"=EXCLUDED."name" RETURNING "id"    (SQLite)
```

- `InsertRows` sets the query type to `INSERT` unless `Replace` was called
  first (`REPLACE INTO ... VALUES (...),(...)`). Every row must have one
  value per column; later calls must use the same column list.
- `Values` takes the sorted keys of the first map as columns; every map
  must have exactly those keys.
- Values render like `Set` assignments (`psql.Raw`, `psql.Incr`, ... are
  expanded) and are bound as arguments. Conflict clauses and `Returning`
  apply to all rows.
- Rows cannot be mixed with `Insert` / `Set` values in the same query.

For objects, `psql.BulkInsert` (below) builds these statements for you.

## JSON expressions

The JSON helpers take the column as a name string or as an expression
(`psql.F`, `psql.Raw`, a subquery) followed by a path: object keys, or array
positions for elements that parse as an integer. Paths are rendered as
literals, so JSON indexes can be used; values are bound as arguments.

| Helper | PostgreSQL | MySQL / MariaDB | SQLite |
|--------|------------|-----------------|--------|
| `JSONGet(f, "a", "b")` | `"f"->'a'->'b'` | `JSON_EXTRACT("f",'$.a.b')` | `json_extract("f",'$.a.b')` |
| `JSONGetText(f, "a", "b")` | `"f"->'a'->>'b'` | `JSON_UNQUOTE(JSON_EXTRACT("f",'$.a.b'))` | `json_extract("f",'$.a.b')` |
| `JSONContains(f, v)` | `"f" @> $1::jsonb` | `JSON_CONTAINS("f",?)` | error |
| `JSONHasKey(f, "a")` | `"f" ? $1` | `JSON_CONTAINS_PATH("f",'one','$.a')` | `json_type("f",'$.a') IS NOT NULL` |
| `JSONSet(f, []string{"a","b"}, v)` | `jsonb_set("f",'{a,b}',$1::jsonb,true)` | `JSON_SET("f",'$.a.b',CAST(? AS JSON))` | `json_set("f",'$.a.b',json(?))` |

```go
type Profile struct {
    psql.Name `sql:"profiles"`
    ID        uint64         `sql:",key=PRIMARY"`
    Data      map[string]any `sql:",import=JSON,format=json"`
    DataIdx   psql.Key       `sql:",type=GIN,fields='Data'"` // PostgreSQL: indexes @> and ?
}

// compare an extracted value
admins, err := psql.Fetch[Profile](ctx, psql.Equal(psql.JSONGetText("Data", "role"), "admin"))
// PostgreSQL: WHERE ("Data"->>'role'=$1)
// MySQL:      WHERE (JSON_UNQUOTE(JSON_EXTRACT("Data",'$.role'))=?)
// SQLite:     WHERE (json_extract("Data",'$.role')=?)

// select JSON values, order by one
q := psql.B().Select("ID", psql.JSONGet("Data", "address"), psql.JSONGetText("Data", "tags", "0")).
    From("profiles").
    OrderBy(psql.JSONGetText("Data", "rank"))
// SELECT "ID","Data"->'address',"Data"->'tags'->>0 FROM "profiles" ORDER BY "Data"->>'rank'
sorted, err := psql.Fetch[Profile](ctx, nil, psql.Sort(psql.JSONGetText("Data", "rank")))

// containment (PostgreSQL @>, MySQL JSON_CONTAINS): every key of the value
// must be present with the same value
q = psql.B().Select().From("profiles").Where(psql.JSONContains("Data", map[string]any{"role": "admin"}))
// SELECT * FROM "profiles" WHERE ("Data" @> $1::jsonb)    with $1 = {"role":"admin"}

// as WHERE map values the map key is the column; Not works
q = psql.B().Select().From("profiles").Where(map[string]any{
    "Data": psql.JSONHasKey(nil, "email"),
})
q = psql.B().Select().From("profiles").Where(map[string]any{
    "Data": &psql.Not{V: psql.JSONContains(nil, map[string]any{"role": "admin"})},
})

// update one value in place, creating the key when missing
q = psql.B().Update("profiles").Set(map[string]any{
    "Data": psql.JSONSet("Data", []string{"prefs", "theme"}, "\"dark\""),
}).Where(map[string]any{"ID": 1})
// PostgreSQL: UPDATE "profiles" SET "Data"=jsonb_set("Data",'{prefs,theme}',$1::jsonb,true) WHERE ("ID"=$2)
// MySQL:      UPDATE "profiles" SET "Data"=JSON_SET("Data",'$.prefs.theme',CAST(? AS JSON)) WHERE ("ID"=?)
// SQLite:     UPDATE "profiles" SET "Data"=json_set("Data",'$.prefs.theme',json(?)) WHERE ("ID"=?)
```

Values given to `JSONContains` and `JSONSet` are marshaled with
`encoding/json`, except `string`, `[]byte` and `json.RawMessage`, which must
already be JSON text: a Go string `"dark"` is therefore passed as
`"\"dark\""` (or as a non-string value, e.g. a struct or map, to be
marshaled). `JSONGet` keeps the JSON type (strings stay quoted on PostgreSQL
and MySQL); `JSONGetText` unquotes, which is what you want for comparisons.
On PostgreSQL the `JSONSet` column must be `jsonb`, which is what
`import=JSON` declares. SQLite has no containment operator, so
`JSONContains` fails there with `ErrNotSupported`.

## Full-text search

`psql.FullText(query, fields...)` is a match condition over one or more
text columns; `psql.FullTextRank` is the corresponding relevance score.
Fields are column names or expressions, optionally followed by a mode
(`FullTextNatural`, the default; `FullTextBoolean` for search-engine style
operators; `FullTextPhrase` for a consecutive phrase) and options
(`FullTextLanguage("english")`, the PostgreSQL text search configuration,
`simple` by default and ignored on MySQL).

```go
q := psql.B().Select().From("posts").Where(psql.FullText("go generics", "Title", "Body"))
// PostgreSQL: WHERE (to_tsvector('simple', coalesce("Title",'') || ' ' || coalesce("Body",'')) @@ plainto_tsquery('simple', $1))
// MySQL:      WHERE (MATCH("Title","Body") AGAINST (? IN NATURAL LANGUAGE MODE))
// SQLite:     ErrNotSupported (use an FTS virtual table with psql.Raw)

psql.FullText(`"exact phrase" -draft`, psql.F("Body"), psql.FullTextBoolean, psql.FullTextLanguage("english"))
// PostgreSQL: to_tsvector('english', ...) @@ websearch_to_tsquery('english', $1)
// MySQL:      MATCH("Body") AGAINST (? IN BOOLEAN MODE)

// as a WHERE map value the map key is the (single) column searched
psql.B().Select().From("posts").Where(map[string]any{"Body": psql.FullText("go generics", psql.FullTextPhrase)})
// PostgreSQL: ... @@ phraseto_tsquery('simple', $1)
// MySQL:      MATCH("Body") AGAINST (? IN BOOLEAN MODE)   (the query is quoted)

// relevance: ts_rank(...) on PostgreSQL, MATCH ... AGAINST on MySQL
rank := psql.FullTextRank("go generics", "Title", "Body")
q = psql.B().Select(psql.F("*"), rank).From("posts").
    Where(psql.FullText("go generics", "Title", "Body")).
    OrderBy(rank.Desc()).Limit(10)
```

To make the search indexed, declare a key matching the searched columns.
MySQL and MariaDB need a `FULLTEXT` key covering exactly the same column
list; PostgreSQL needs a `GIN` key on the same `to_tsvector` expression.
Keys the engine does not know are skipped, so both can live on one struct:

```go
type Post struct {
    psql.Name `sql:"posts"`
    ID        uint64   `sql:",key=PRIMARY"`
    Title     string   `sql:",type=VARCHAR,size=255"`
    Body      string   `sql:",type=TEXT"`
    Search    psql.Key `sql:"posts_search,type=FULLTEXT,fields='Title,Body'"`
    TextIdx   psql.Key `sql:"posts_text,type=GIN,expression=\"to_tsvector('simple', coalesce({Title},'') || ' ' || coalesce({Body},''))\""`
}
```

### GIN, GIST and expression keys

`type=GIN` and `type=GIST` are PostgreSQL index methods (jsonb containment,
full-text search, ranges, geometry); on CockroachDB a GIN key becomes its
inverted index (see the driver README for what GIST maps to). Other engines
skip these keys. The `expression` attribute
replaces the `fields` list with an indexed expression in which `{Column}`
refers to a column, and `StructKey.Expression()` returns it with the
references quoted (`to_tsvector('simple', coalesce("Title",'') || ...)`),
which the PostgreSQL driver renders as
`CREATE INDEX ... USING gin (<expression>)`.

The tag parser strips quote characters and only preserves the text inside
a quoted value, so the expression must be wrapped in double quotes (written
`\"` inside a Go raw tag); single quotes inside it survive, but the
expression itself cannot contain a double quote. Refer to columns with
`{Column}` rather than quoting them.

## Named locks

`psql.NamedLock(ctx, name, timeout)` acquires a cooperative, server-wide
lock on a name and returns the function releasing it;
`psql.WithNamedLock(ctx, name, timeout, fn)` runs `fn` while holding it.
They serialize application-level operations such as migrations or scheduled
jobs across processes.

```go
release, err := psql.NamedLock(ctx, "nightly-report", 5*time.Second)
if errors.Is(err, psql.ErrLockTimeout) {
    return errors.New("another instance is running the report")
}
if err != nil {
    return err // ErrNotSupported on SQLite and CockroachDB
}
defer release()

err = psql.WithNamedLock(ctx, "migrate", 0, func(ctx context.Context) error {
    return runMigrations(ctx) // ctx carries the transaction holding the lock
})
```

- `timeout` bounds the wait for a lock held by someone else: `0` waits
  indefinitely, a negative value fails immediately when the lock is taken.
  A timeout returns an error wrapping `psql.ErrLockTimeout`.
- Locks belong to a connection. When `ctx` already carries a transaction
  the lock is taken inside it; otherwise `NamedLock` pins a dedicated
  connection (with an open transaction) until `release` is called, which
  must happen exactly once. `WithNamedLock` without a transaction in `ctx`
  begins one, runs `fn` with it and commits when `fn` returns nil.
- MySQL and MariaDB use `GET_LOCK` / `RELEASE_LOCK` (session scope: the
  lock survives transactions); PostgreSQL uses `pg_advisory_xact_lock` on
  a hash of the name (transaction scope: released when the transaction
  ends, whatever `release` does; `pg_try_advisory_xact_lock` for a negative
  timeout and `lock_timeout` for a positive one). CockroachDB has no
  advisory locks and SQLite no named locks: both return `ErrNotSupported`,
  which `Backend.Supports(psql.FeatureAdvisoryLocks)` predicts.

## Identity columns (`autoinc`)

The `autoinc` tag attribute marks an integer column whose value is
generated by the database:

```go
type Event struct {
    psql.Name `sql:"events"`
    ID        int64  `sql:",key=PRIMARY,autoinc"`
    Kind      string `sql:",type=VARCHAR,size=32"`
    Payload   string `sql:",type=TEXT"`
}

ev := &Event{Kind: "login", Payload: "{}"}
err := psql.Insert(ctx, ev)
fmt.Println(ev.ID) // generated by the database
```

- Only one `autoinc` field is allowed per table, and it must be an integer
  kind (or a pointer to one); `psql.Table[T]()` panics otherwise. The
  attribute does not prevent type inference and is kept as `autoinc=1` in
  the resolved attributes for the dialects. `Table[T]().AutoIncField()` and
  `StructField.IsAutoInc()` expose it.
- DDL per engine: `AUTO_INCREMENT` on MySQL and MariaDB,
  `GENERATED BY DEFAULT AS IDENTITY` on PostgreSQL and CockroachDB, nothing
  on SQLite where an `INTEGER PRIMARY KEY` is the rowid and is generated
  automatically (see the driver READMEs for the exact statements).
- `Insert`, `InsertIgnore`, `Replace` and `BulkInsert` leave the column out
  of the statement while the field is zero (or a nil pointer), so the
  database generates it, and populate the field afterwards from `RETURNING`
  (PostgreSQL, CockroachDB) or `LastInsertId` (MySQL, SQLite). Objects
  carrying a value keep it; one call may mix both kinds.
- `Update` never writes an `autoinc` column: identity values are assigned
  by the database and are normally the key the row is addressed by.

Without `autoinc`, `Insert` still populates a zero single-integer primary
key from `LastInsertId` on MySQL and SQLite, but the column is created
without `AUTO_INCREMENT` on MySQL.

## Transactions with options and retries

`psql.TxWithOptions(ctx, opts, cb)` is `psql.Tx` with control over the
transaction:

```go
err := psql.TxWithOptions(ctx, &psql.TxOptions{Isolation: sql.LevelSerializable, MaxRetries: 5}, func(ctx context.Context) error {
    from, err := psql.Get[Account](ctx, map[string]any{"ID": int64(1)}, psql.FetchLock)
    if err != nil {
        return err
    }
    if from.Balance < 10 {
        return errors.New("insufficient funds") // not retryable: returned as is
    }
    from.Balance -= 10
    if err := psql.Update(ctx, from); err != nil {
        return err
    }
    _, err = psql.B().Update("accounts").Set(map[string]any{"Balance": psql.Incr(10)}).Where(map[string]any{"ID": int64(2)}).ExecQuery(ctx)
    return err
})
if errors.Is(err, psql.ErrTxRetriesExhausted) {
    // still conflicting after 6 attempts; errors.As still reaches the driver error
}

// a read-only transaction that is never retried
err = psql.TxWithOptions(ctx, &psql.TxOptions{ReadOnly: true, MaxRetries: -1}, func(ctx context.Context) error {
    _, err := psql.Count[Account](ctx, nil)
    return err
})
```

| Field | Meaning |
|-------|---------|
| `Isolation`, `ReadOnly` | Passed to `database/sql` when the transaction starts. Ignored for nested transactions (savepoints). |
| `MaxRetries` | Re-runs of the callback after a retryable failure. `0` means `psql.DefaultTxRetries` (3), negative disables retries. |
| `Backoff` | `func(attempt int) time.Duration`, attempt 1 for the first retry. `nil` is an exponential backoff with jitter, about 10 ms doubling up to 1 s. |

Retry semantics:

- Only a top-level transaction retries. When the callback, or the commit,
  fails with an error the backend's dialect reports as retryable
  (`RetryableChecker`), the transaction is rolled back and, after the
  backoff, **the callback runs again** with a fresh transaction. The
  callback must therefore be idempotent with respect to everything outside
  the database: do not send emails, publish messages or accumulate results
  in outer variables without resetting them at the start.
- `psql.Tx` is `TxWithOptions(ctx, nil, cb)`: default isolation and up to
  `psql.DefaultTxRetries` retries, so its callback must be re-runnable too.
  Disable retries per call with `MaxRetries: -1` (a `MaxRetries` of `0`
  means the default), or globally by setting `psql.DefaultTxRetries = 0`.
- When the retries are exhausted the last error is returned wrapped with
  `psql.ErrTxRetriesExhausted` (both `errors.Is` on the sentinel and
  `errors.As` on the driver error work). A cancelled context stops the wait
  and returns the cancellation error.
- A nested call (the context already carries a transaction) runs once as a
  savepoint and returns its error unchanged, so the outer transaction can
  retry as a whole.
- `psql.IsRetryable(err)` asks every registered dialect. What counts as
  retryable per driver: serialization failures and deadlocks (SQLSTATE
  `40001`, `40P01`) on PostgreSQL, the same plus "restart transaction"
  errors on CockroachDB, deadlocks and lock wait timeouts (errors 1213 and
  1205) on MySQL and MariaDB, "database is locked" on SQLite.

`Tx` and `TxWithOptions` also interact with named locks: a `NamedLock`
taken inside the callback is released with the transaction on PostgreSQL.

## Bulk insert

`psql.BulkInsert(ctx, rows, opts...)` inserts many objects of one table
with as few statements as possible:

```go
events := make([]*Event, 0, 10000)
for i := 0; i < 10000; i++ {
    events = append(events, &Event{Kind: "import", Payload: fmt.Sprintf(`{"i":%d}`, i)})
}
err := psql.BulkInsert(ctx, events, psql.BulkBatchSize(1000), psql.BulkNoHooks())

// all-or-nothing, skipping rows that already exist
err = psql.Tx(ctx, func(ctx context.Context) error {
    return psql.BulkInsert(ctx, events[:10], psql.BulkIgnore())
})
```

| Option | Effect |
|--------|--------|
| `psql.BulkBatchSize(n)` | Rows per `INSERT` statement (default `psql.DefaultBulkBatchSize`, 500). The size is also capped so that rows × columns stays under the engine's parameter limit: 65535 on PostgreSQL and MySQL, 32766 on SQLite. |
| `psql.BulkIgnore()` | Skip conflicting rows (`INSERT IGNORE`, `INSERT OR IGNORE`, `ON CONFLICT DO NOTHING`). Generated keys are not populated and the native loader is not used. |
| `psql.BulkNoHooks()` | Skip the `BeforeSave`/`BeforeInsert` and `AfterInsert`/`AfterSave` hooks. |

- Two paths. When the dialect implements `BulkInserter` (the PostgreSQL
  driver's `COPY`), no generated key needs to be read back and `BulkIgnore`
  is not set, every row is exported and handed to it in one go. Otherwise
  multi-row `INSERT` statements are issued in batches. A dialect may
  decline a particular load (a type `COPY` cannot carry) with
  `ErrNotSupported`, in which case the `INSERT` path is used.
- Rows whose `autoinc` field is zero are inserted without that column; a
  batch never mixes rows with and without it, so mixing them costs extra
  statements but keeps the insertion order.
- Generated keys: on PostgreSQL and CockroachDB the rows are returned with
  `RETURNING` and scanned back into the objects in order (refreshed like
  `Insert` does); on MySQL and MariaDB the field is set to
  `LastInsertId` + row index, which InnoDB guarantees for a single
  multi-row `INSERT` in which no row supplies its own value; on SQLite the
  rowids of one multi-row statement are not guaranteed to be consecutive,
  so the field is left unset (use `Insert` when the ids matter).
- Hooks: `BeforeSave` and `BeforeInsert` run for every row first, then the
  rows are written, then `AfterInsert` and `AfterSave` run per row after
  each batch. A failure in a later batch leaves the earlier batches written
  and their hooks fired; wrap the call in `psql.Tx` for all-or-nothing
  behaviour. An empty slice is a no-op.

## Driver-specific extras

The driver modules add product-specific behaviour on top of the core. The
exact SQL is documented in each driver's README.

- **PostgreSQL / CockroachDB** (`psql-pgsql`): product detection
  (`VariantCockroachDB` from the version string), identity DDL, GIN/GIST
  and full-text index creation, retry classification, advisory locks, `COPY`
  bulk loading, and `pgsql.Listen` / `pgsql.Notify` for PostgreSQL's
  `LISTEN` / `NOTIFY` (`FeatureListenNotify`; not available on CockroachDB).
  Native column types such as `uuid`, `inet`, `cidr` and `timestamptz` are
  available through `type=`. On CockroachDB the `psql.Name` tag accepts
  the table attributes `ttl_expire_after`, `ttl_expiration_expression`
  (row-level TTL, `FeatureRowTTL`) and `locality`.
- **MySQL / MariaDB** (`psql-mysql`): MariaDB detection
  (`VariantMariaDB`), `AUTO_INCREMENT` for `autoinc` columns, `GET_LOCK`
  named locks, retries on errors 1213 and 1205, and `RETURNING` on
  `INSERT` and `DELETE` for MariaDB.
- **SQLite** (`psql-sqlite`): `RETURNING` on every statement, retries on
  "database is locked", rowid identity columns.

## Writing a dialect

Drivers register a `psql.Dialect` and opt into behaviour through optional
interfaces. The ones behind this page:

| Interface | Used by | Purpose |
|-----------|---------|---------|
| `RetryableChecker` | `Tx`, `TxWithOptions`, `IsRetryable` | `IsRetryable(err) bool` reports transient failures worth re-running the transaction for. |
| `LockRenderer` | `NamedLock`, `WithNamedLock` | `AcquireLockSQL(name, timeout)` returns the statement (and arguments) that blocks for at most `timeout` (`0` forever, negative: try without waiting) and yields one value that is true or 1 on success, or no result set; `ReleaseLockSQL(name)` may return `""` when the lock goes away with the transaction. |
| `LockTimeoutChecker` | `NamedLock` | `IsLockTimeout(err) bool` for products whose acquisition statement reports a timeout as an error (PostgreSQL `lock_timeout`, SQLSTATE `55P03`), mapped to `ErrLockTimeout`. |
| `BulkInserter` | `BulkInsert` | `BulkInsert(ctx, be, table, columns, rows)` loads rows natively (`COPY`); return an error wrapping `ErrNotSupported` to fall back to multi-row `INSERT`. |
| `ReturningRenderer` | `Insert`, `BulkInsert`, the builder | `SupportsReturning() bool`: the object functions use `RETURNING` to refresh objects. |
| `ReturningStatements` | the builder | `SupportsReturningFor(stmt) bool` with `"INSERT"`, `"UPDATE"` or `"DELETE"`, for products supporting `RETURNING` on some statements only (MariaDB). |
| `VariantAware` | `Backend.Supports`, the builder | `SupportsFeature(v Variant, feature string) bool` overrides the engine-level defaults for the `Feature*` constants. |

```go
type myDialect struct{ /* ... */ }

func (myDialect) IsRetryable(err error) bool { return sqlState(err) == "40001" }

func (myDialect) AcquireLockSQL(name string, timeout time.Duration) (string, []any, error) {
    return "SELECT pg_advisory_xact_lock(hashtext($1))", []any{name}, nil
}
func (myDialect) ReleaseLockSQL(name string) (string, []any, error) { return "", nil, nil }

func (myDialect) SupportsReturningFor(stmt string) bool { return stmt != "UPDATE" }

func (myDialect) SupportsFeature(v psql.Variant, feature string) bool {
    return feature == psql.FeatureCTE
}
```

Feature names (`psql.FeatureReturning`, `FeatureAdvisoryLocks`,
`FeatureListenNotify`, `FeatureAsOfSystemTime`, `FeatureRowTTL`,
`FeatureDistinctOn`, `FeatureCTE`, `FeatureFullText`, `FeatureJSON`,
`FeatureVectors`, `FeatureIdentityColumns`, `FeatureBulkCopy`) are plain
strings, so a dialect can also define its own. The core consults the
variant for the few rendering decisions it makes itself (`RETURNING`
availability, `DISTINCT ON`, `AS OF SYSTEM TIME`, MySQL lock syntax,
`EXPLAIN` spelling); everything else goes through these interfaces.
